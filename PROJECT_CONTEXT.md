# Project context

Read this before making changes. It records decisions and constraints that are
**not** visible from the code, and several rules that exist because something
was already gotten wrong.

`AGENTS.md` is generated by Laravel Boost (`boost.json` has `"guidelines": true`)
and will be overwritten. Do not put durable knowledge there.

---

## What this is

A personal finance tracker. Transactions in multiple currencies, aggregated into
one base currency, with insights, CSV import, and recurring bills.

Laravel 13 / PHP 8.3 / Tailwind. PostgreSQL in development, SQLite in tests.

---

## The invariant that matters most

**Every monetary figure the user sees is summed from `base_amount`, never from
`amount`.**

A transaction stores what the user entered (`amount`, `currency`) alongside a
frozen conversion (`base_amount`, `base_currency`, `applied_rate`), taken once at
entry time by `App\Actions\ConvertTransactionAmount`. Exchange rates move;
historical totals must not.

Two rules follow, both violated at least once already:

1. **Every query that aggregates money must also filter
   `base_currency = config('finance.base_currency')`.** Checking only
   `base_amount IS NOT NULL` is not enough. A row converted under a previous
   base currency still carries a `base_amount`, so summing it alongside current
   rows silently blends two currencies. See `TransactionController::index` and
   `SpendingStatsService::expenseQuery`.

2. **Nothing may write `amount` without going through
   `ConvertTransactionAmount`.** The create form, CSV import, and recurring
   generation all route through it. A direct `Transaction::create()` with an
   amount produces a row that is invisible to every total.

## Period boundaries

Date filtering and "current period" logic must bound to `startOfDay()` /
`endOfDay()` / `endOfMonth()`, never to `now()`.

Bounding a month at `now()` drops anything recorded earlier today whose time of
day is later than the clock. Because `APP_TIMEZONE` and the timezone the user
actually types in do not always match, that is most of a day's entries, and the
category breakdown silently disagrees with the headline total. It hid a
transaction and a whole category before.

Use `whereDate()` for comparisons against `date` columns. SQLite stores date
columns with a time component (`2026-10-01 00:00:00`) while PostgreSQL truncates
on insert, so a raw string comparison against a bare date is correct on one and
wrong on the other.

## Mass assignment

`user_id` is deliberately **not** in `Transaction::#[Fillable]`. Always create
through the relation:

```php
$user->transactions()->create([...]);
```

`Transaction::create([... 'user_id' => $id])` drops it silently and produces a
row with no owner. This caused a NULL violation that was only visible because a
test caught the swallowed exception.

## Money storage

- Amounts: `decimal(12, 2)`. Stored unsigned; direction is carried by `type`.
- Exchange rates: `decimal(18, 8)`. Money-scale precision collapses a rate.
- Never do arithmetic on a money value in the model layer. `SpendingStatsService`
  computes in SQL; the AI insight service receives finished figures and narrates
  them, which is what keeps invented numbers out.

## Base currency

`config('finance.base_currency')`, env `FINANCE_BASE_CURRENCY`, default `CNY`.

Changing it does **not** retroactively convert existing rows. They keep the base
currency they were converted into and are excluded from totals until
re-run:

```bash
php artisan finance:backfill-base-amounts
```

CNY is preferred as the base because `FrankfurterRateProvider` deliberately never
inverts a rate: the provider rounds to five decimals, so CNY→IDR stays precise
while IDR→CNY loses roughly 1.2%.

## Scheduled work

`routes/console.php`:

- `finance:generate-recurring` — daily at 04:00.

Requires the scheduler to be running in development:

```bash
php artisan schedule:work
```

Useful flags: `--dry-run`, `--date=YYYY-MM-DD`, `--user=`, `--no-reminders`.

Recurring occurrences are idempotent by construction: a unique index on
`(recurring_transaction_id, occurrence_on)` means an occurrence can be posted at
most once however many times the scheduler runs. The application-level existence
check is only an optimisation; the index is the guarantee. Do not remove it.

## Testing

```bash
php artisan test --compact
vendor/bin/pint --dirty --format agent
```

- SQLite in-memory, so tests do **not** need network. Fake exchange rates with
  `Http::fake([...])` or the snapshot silently comes back null.
- `tests/Feature/LocalizationTest.php` enforces that every `__('...')` key in a
  Blade file exists in `lang/id.json`. Adding a string to a view without a
  translation fails the suite. Keep the two in step.
- Date comparisons should use `CarbonImmutable`.

## Gotchas already paid for

- **`@push('scripts')` needs `@stack('scripts')` in the layout.** It was missing;
  every pushed script, including the entire CSV import preview UI, was discarded
  silently. Tests that hit endpoints directly never noticed.
- **New Tailwind classes need `npm run build`.** Classes are only generated if
  present at build time. A missing class degrades layout silently — the calendar
  rendered as a bare list of numbers.
- **Carbon's `canBeCreatedFromFormat` returns false for valid input** in some
  cases (e.g. `'Y-m-d'` against `'2026-10-01'`). Prefer try/catch plus a
  round-trip check.
- **Adding a month to the 31st overflows.** `addMonth()` on 31 January gives 3
  March. `RecurringFrequency` derives occurrences from an anchor with clamping;
  do not replace it with repeated addition.
- **Checkbox `required` rejects exactly the request that unticks it.** An
  unchecked checkbox submits no field. Absent means false.
- **Union operator does not overwrite.** `$row + ['key' => $v]` keeps `$row`'s
  value. Use a spread.

## Conventions

- Form requests own validation rules; controllers stay thin.
- Statistics live in services, not models. `app/Services`.
- Reuse `CategoryService` for category dropdowns — categories are free text, so
  there is no lookup table to keep in sync.
- Routes for literal paths must be registered **before** a resource route that
  would otherwise capture them as a wildcard.
- Money display uses `number_format($value, 2)` with the currency in a muted
  sibling element.

## Commands

```bash
php artisan db:seed --class=SpendingDemoSeeder   # demo data; DELETES that user's transactions
php artisan finance:backfill-base-amounts       # reconvert after a base currency change
php artisan finance:generate-recurring --dry-run
```

`SpendingDemoSeeder` writes CNY explicitly. It used to stamp rows with whatever
base currency was configured and a rate of 1, which labelled CNY-magnitude
figures as IDR. If demo amounts look implausibly small or large, check this
seeder first.

## Known gaps

- The CSV importer has never been run against a real bank or payment-app export.
  Its column guesser handles common header names; the actual file format is
  unknown, and GBK-encoded exports are not handled.
- There is no duplicate detection on import beyond removing a whole batch from
  `/transactions/imports`.
- Staged import uploads in `storage/app/imports` are never swept.
- No browser-level tests. Two features were broken visually while their HTML
  structure tests passed.
